# 墨墨记忆卡（Markji）制卡

用官方开放 API 把学习材料做成 Markji 卡片。核心难点不在调接口，而在**卡片内容必须是一整段合法的 Markji 专用语法**——语法写错不会报错，只会静默渲染成一团乱码。

## 起手动作

```bash
S=~/.claude/skills/markji/scripts/markji.py   # 已全局软链；在 my_markji 仓库内也可写 .claude/skills/markji/scripts/markji.py
python3 $S whoami
```

凭证读取顺序：环境变量 `MAIMEMO_TOKEN` → **当前目录**向上找 `.env` → **脚本真实位置**向上找 `.env`。
最后这条让 skill 软链到 `~/.claude/skills/` 后，在任何项目目录下都能找到 my_markji 仓库里的 `.env`。
凭证**绝不能**出现在代码、文档、提交信息或终端回显中。`.env` 已被 `.gitignore` 忽略，不要移除该规则。

## 必须先知道的三条边界

1. **开放 API 只能写卡片和媒体。** 不能建/删牌组，不能建/删章节，**也不能删卡片**。
   牌组和章节要用户先在 App 或网页端建好；写进去的卡片只能在 App 端删。
2. **写入是不可逆的。** 首次向某个牌组写卡前，先向用户确认目标牌组/章节和卡片内容。
3. **`content` 是一整段语法文本**，`grammar_version` 固定为 `3`。更新是全量替换而非增量补丁。

官方 OpenAPI 文档有两处与实现不符，`markji.py` 已处理，**直接手写 curl 时要注意**：
创建卡片的请求体**必须省略** `deck`/`chapter`（否则报 `not a valid ObjectId`）；
上传媒体必须用 `multipart/form-data` 而非 JSON。详见 `references/api.md`。

## 标准工作流

```bash
python3 $S decks                      # 找到目标牌组，拿 mkjd_ 开头的 id
python3 $S chapters <deck>            # 拿 mkjch_ 开头的章节 id
python3 $S cards <deck>               # 看已有卡片，模仿该牌组既有的排版风格
python3 $S card <deck> <card>         # 读单张卡片的完整语法

# 把卡片内容写进文件（真实换行，UTF-8），先离线校验
python3 $S lint card.txt

# 校验通过后写入；create/update 内部会再校验一次，有错误直接中止
python3 $S create <deck> <chapter> --file card.txt --dry-run   # 先看要发什么，不写入
python3 $S create <deck> <chapter> --file card.txt
python3 $S update <deck> <card> --file card.txt

# 媒体：先上传拿 file.id，再把 id 写进卡片语法
python3 $S upload ./pic.png --deck <deck>
python3 $S query-files <fileId> ...

# 写完批量自检：卡片数、章节内顺序、媒体是否被服务端关联、逐张语法
python3 $S verify <deck> <chapter>
```

一次做多张卡时，**每张卡一个文件**，`lint` 全部通过后再逐张 `create`，请求间隔 ≥0.5s（频控 10 秒 20 次）。

## 从文档批量制卡

把一份材料（Markdown、讲义、笔记）做成整套卡片时，按这个顺序走：

1. **读全文，先切知识点**，再想卡片形态。跳过例题、习题、练习章节，除非用户明确要求收进去。
2. **先把所有图片传完**，把 `路径 → file.id` 记进一份 manifest（JSON），后面统一回填。
   不要边建卡边传图——传图失败会留下半套卡。
3. **把所有卡片写进一个文件，用 `batch` 一次建完**——不要循环调用 `create`。
   卡片之间用独占一行的 `@@@` 分隔（不能用 `---`，那是答案线）：

   ```bash
   python3 $S batch <deck> <chapter> --file cards.txt --manifest out.json
   ```

   `batch` 会先校验**全部**卡片，任何一张有语法错误就整体中止、一张都不建，
   避免留下半套卡；通过后按顺序逐张提交（默认间隔 0.6s），把 `card_id` / `root_id`
   增量写进 manifest，终端只输出汇总。失败时给出失败索引，用 `--start N` 续传，
   不会重复创建已成功的卡。

   顺序：**省略 `--order`** 即按文件中的先后追加到章节末尾。
   `order` 是相对整个章节的 0 基插入索引，非空章节里从 0 递增会把新卡全插到旧卡前面。
4. **`verify` 收尾**，核对卡片总数、章节内顺序、每张卡的 `files` 是否都解析成功。
5. 失败的重试一次；仍失败的**记下来报告给用户**，不要静默跳过。

完成后向用户汇报：读了哪个文件、提取多少知识点、生成多少张卡、写进哪个牌组/章节、
API 确认的卡片总数与顺序、用了哪些图（`file.id` 与卡片的对应关系）、失败或跳过的内容及原因。

### 两个批量制卡专属的坑

- **卡片正文里全是 LaTeX 花括号**（`\frac{a}{b}`、`\begin{aligned}`）。做模板替换时
  **禁止用 f-string、`str.format()`、`%` 格式化**——花括号会被当成占位符而报错或被吃掉。
  需要占位时用 `@IMG_1@` 这类令牌配合 `str.replace()`。
- **Markji 没有表格语法，也没有代码块语法。** 从 Markdown 转卡片时，
  `| a | b |`、\`\`\` 围栏、`#` 标题、`**加粗**` 都会**原样显示成文本**。
  表格要拆成 `[P#L#…]` 列表或多张卡；标题用 `[P#H1#…]`，加粗用 `[T#B#…]`。

## 单句制卡（英语口语卡）

用户丢来**一句英文**（或一个表达、一句想说的中文）时，直接做成一张卡，不需要 md 文件：

```bash
python3 $S create <deck> <chapter> --file - <<'CARD'
<卡片内容>
CARD
```

`--file -` 读标准输入，配合 heredoc 一步到位。写入前先 `--dry-run` 给用户过目。

**多于一张就改用 `batch`**（同样支持 `--file -`），一次工具调用建完所有卡：

```bash
python3 $S batch <deck> <chapter> --file - --manifest out.json <<'CARDS'
<第一张>
@@@
<第二张>
CARDS
```

### 房屋风格（务必沿用）

用户 Speaking 系列的句子卡统一用这套结构，新卡必须对齐：

```text
[P#H1,center#[T#B#<中文意思>]]
---
<英文句子，关键表达标蓝>

[T#B,!78909c#📌 重点短语]
[P#L#[T#B#<表达>] — [T#!888888#<中文释义>]]
```

规则：

- **正面是中文，背面是英文**——这是中译英的产出练习，不要做成英译中。
- 关键表达用 `[T#B,!1a73e8#…]`（加粗＋蓝），**每张 2–4 处**，标满等于没标。
- **屈折后缀留在标签外**：写 `[T#B,!1a73e8#crash]ed`，不要把 `crashed` 整个包进去——
  这样标出的是可迁移的词元，不是这一句里的特定形态。
- **背面不放中译**，也**不放音标**——正面已经是中文；发音靠墨墨 App 复习时的自带朗读。
- **重点短语区**：小标题 `[T#B,!78909c#📌 重点短语]`，逐条列出标蓝过的表达，
  格式固定 `[P#L#[T#B#表达] — [T#!888888#释义]]`——表达只加粗不加下划线，释义灰色，
  破折号用半角 `—` 两侧各一空格。释义里可补搭配说明，如「后接名词/动名词」。
- 小标题的灰蓝色固定 `!78909c`；emoji 固定 📌。
- 一句话能同时给出多种地道说法时，用 ` / ` 在同一行并列，例如
  `Knode-recall [T#B,!1a73e8#crash]ed. / The service went down.`

模板见 `templates/sentence-en.txt`。已建的旧红色/音标卡片暂不批量迁移，按需逐张更新。

### 选牌组

先 `decks` 列出牌组按主题匹配（Speaking - Social / Government / Culture / Internet …）。
匹配不到就问用户，**不要自己新建**——API 建不了牌组。
往非空章节追加时省略 `--order`。

## 内容设计原则

语法正确 ≠ 卡片好用。生成内容时遵守：

- **最小信息原则**：一张卡只考一个原子知识点。内容长就拆卡，不要一卡多问。
- **不照抄整段大文本**。整段贴进来的卡在复习时无法判断对错，等于没做。
- 问答类用「问题 —— 答案」；定义、枚举、清单类用挖空 `[F#n#…]` 做主动回忆。
- 公式多的主题，给每张卡一个简短中文标题 `[P#H1,center#[T#B#…]]`，否则复习时认不出是哪个公式。
- **每张卡配图不超过 2 张**；图片放答案面，或作为「看图说出这是什么」的问面。
- **遇到本 skill 没覆盖的效果，退回纯文本写法**，不要按标签名猜语法。宁可朴素，不要渲染成乱码。

## 生成卡片内容的规矩

写卡片前**必读** `references/card-syntax.md`。最容易翻车的几点：

- **真实换行是语法的一部分**。绝不能写成字面 `\n`，也不能把整张卡压成一行。
- **`---` 是答案线**，独占一行、前后无空格。标题标签不代替答案线。
- **块级语法必须顶格**：`[P#…]`、`[Choice#…`、`[Pic#…#]`、独立公式、`---`。行内公式不受此限。
- **样式合并进一个标签**：写 `[T#B,U,!e53935#重点]`，不要写 `[T#B#[T#U#重点]]`。
- **颜色是不带 `#` 的 6 位小写十六进制**：`!e53935` ✓，`!#E53935` ✗。
- **普通文字里的中括号写成 `\[` `\]`**，否则会提前闭合外层标签。
- **公式一律 `[E##LaTeX]`**（KaTeX 渲染），内部不再套 `$`、`$$`、`\(`、`\[`。
- **公式挖空是 `E` 内嵌 `F`**：`[E##k=[F#1#\frac{\Delta y}{\Delta x}]]`，不是反过来。
- **选择题类型由 `*` 的个数决定**：一个用 `[Choice##`，两个以上必须 `[Choice#multi#`；选项行以 `* ` / `- ` 开头（符号后有空格），结束的 `]` 独占一行。
- **媒体只能用上传返回的真实 `file.id`**，大小写敏感，绝不能填文件名、路径或 URL；不要编造 ID。
- **卡片引用填 `root_id`**（`mkjr_…`）而不是 `card.id`，最多 5 个、用 `-` 连接。

模板见 `templates/`，可直接复制后替换占位符——**所有 `<…>` 占位符都必须替换**。

## 「美观」的实际含义

Markji 卡片的可读性主要靠这几件事，照做即可：

- 正面用 `[P#H1,center#[T#B#…]]` 立标题；有外文对照时用 `[P#center#…]` 放第二行。
- 答案面只强调**真正的考点**：用 `[T#B,!e53935#…]` 标 2–4 处即可，标满等于没标。
- 补充信息（音标、词源、出处）用低饱和灰 `[T#!888888#…]` 降权。
- 需要罗列时用 `[P#L#…]` 配 `[P#L,I2#…]` 做层级，不要堆砌裸换行。
- 需要主动回忆时用 `[F#n#…]` 挖空，同一组用同一编号。
- 一张卡只考一个点。内容长就拆卡，不要靠缩小信息密度硬塞。
